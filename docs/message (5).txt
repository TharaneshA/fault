  Slide 2: Problem Statement

  "When a microservice fails, it generates alerts across metrics, logs, and traces. 82% of organizations take over an hour to resolve incidents, up from just 47% in 2021. The problem isn't lack of data — it's lack of correlation. Current methods have three gaps: they don't scale to real systems with 200+ metrics, they only capture simple A-causes-B relationships missing multi-service cascades, and they can't explain WHY something is the root cause. Our project addresses all three."

  Slide 6: Existing Solutions

  "DiagFusion is our base paper — it uses GNN on multi-modal events but lacks causal reasoning and interpretability. MULAN from WWW 2024 adds contrastive learning but still uses pairwise graphs and doesn't handle traces explicitly. RUN uses Neural Granger which is good for causality but struggles at scale. Commercial tools like Dynatrace have false positive issues in Kubernetes environments. The three gaps across all methods are: scalability, multi-way causality, and interpretability."

  Slide 7: Proposed Solution

  "We extend DiagFusion with three components. CMEA uses MULAN-style contrastive learning for multi-modal alignment. INGD combines Neural Granger with a hierarchical divide-and-conquer approach from RCD to handle scale, then builds hypergraphs from CHASE to capture multi-way cascades.   Slide 9: INGD

  "The key innovation here is solving scalability. Neural Granger alone fails on 200+ metrics. We use RCD's approach: split metrics by service into small clusters, run Neural Granger locally on each, merge candidates, and recursively process until we find the root cause. Then instead of a regular graph, we build a hypergraph where each hyperedge captures an entire cascade path — not just A-to-B but the whole chain A-B-C-D together. CHASE showed this gives 36% better accuracy."

  Slide 10: CCRE

  "For explanations, we don't just prompt an LLM directly. We use retrieval-augmented generation — when a new incident occurs, we search a vector database of past incidents, retrieve similar cases, and give that context to the LLM. This means explanations reference your actual system history: 'This is similar to the CPU saturation incident last month in ts-order-service.' Operators can verify against known incidents, and confidence improves with more historical data."

  Slide 11: Scalability

  "Three techniques make this scale. First, HDBSCAN clustering reduces millions of traces to cluster representatives — from Sleuth at ASPLOS 2023. Second, hierarchical causal discovery from RCD means we don't build the full causal graph — we divide and conquer. Third, hypergraph pruning focuses analysis on high-anomaly regions. Together, these let us handle Train-Ticket's 212 metrics where other methods fail."
