  Part 1: Individual Member Contributions

  Member A: CMEA (Contrastive Multi-Modal Event Alignment)

  What It Does:
  Transforms raw metrics, logs, and traces into aligned, unified event representations that capture both cross-modal patterns and modality-specific signals.

  Reference Papers:
  ┌───────┬───────────────┬─────────────────────────────────────────────────────────────────────────────────────────┐
  │ Paper │     Venue     │                                  What We Take From It                                   │
  ├───────┼───────────────┼─────────────────────────────────────────────────────────────────────────────────────────┤
  │ FOCAL │ NeurIPS 2023  │ Factorized contrastive learning to separate shared vs modality-specific representations │
  ├───────┼───────────────┼─────────────────────────────────────────────────────────────────────────────────────────┤
  │ Nezha │ ESEC/FSE 2023 │ Event transformation approach (converting metrics/logs/traces into homogeneous events)  │
  ├───────┼───────────────┼─────────────────────────────────────────────────────────────────────────────────────────┤
  │ MULAN │ WWW 2024      │ Contrastive learning for modality-invariant representations in microservices            │
  └───────┴───────────────┴─────────────────────────────────────────────────────────────────────────────────────────┘
  Technical Details:

  ┌─────────────────────────────────────────────────────────────────────────┐

  │  │  │   Shared    │     │   Metric    │     │    Log      │       │   │
  │  │  │  Encoder    │     │  Specific   │     │  Specific   │       │   │

  │  │                             ▼                                   │   │
  │  │  Contrastive Loss: Align same-time events, separate different  │   │
  │  │  Orthogonality Loss: Keep shared and specific spaces separate  │   │
  │  │  (from FOCAL paper)                                            │   │
  │  └─────────────────────────────────────────────────────────────────┘   │
  │                              │                                          │
  │                              ▼                                          │
  │  Output: Unified event embeddings per service                          │
  │  h_i = [shared_repr; metric_specific; log_specific; trace_specific]    │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  Key Equations (from FOCAL):
  Total Loss = L_contrastive + λ₁ * L_orthogonality + λ₂ * L_reconstruction

  L_contrastive: Pulls together representations from same failure, pushes apart different
  L_orthogonality: Ensures shared and specific representations don't overlap

  What DiagFusion Does (that we improve):
  - DiagFusion uses simple fastText embedding on serialized events
  - Treats all modalities equally after serialization
  - Loses cross-modal correlation patterns

  Our Improvement:
  - Learn WHAT patterns are shared across modalities (e.g., "memory spike + timeout log + slow trace")
  - Learn WHAT patterns are unique to each modality
  - Better temporal alignment of events across modalities

  Member B: INGD (Interpretable Neural Granger with Decomposition)

  What It Does:
  Discovers causal relationships between services (not just correlations) and explains WHY each causal edge exists.

  Reference Papers:
  ┌──────────────────────────┬────────────────┬─────────────────────────────────────────────────────────────────────────────────────────┐
  │          Paper           │     Venue      │                                  What We Take From It                                   │
  ├──────────────────────────┼────────────────┼─────────────────────────────────────────────────────────────────────────────────────────┤
  │ RUN                      │ AAAI 2024      │ Neural Granger causal discovery for microservice RCA                                    │
  ├──────────────────────────┼────────────────┼─────────────────────────────────────────────────────────────────────────────────────────┤
  │ CausalFormer             │ IEEE TKDE 2024 │ Multi-kernel causal convolution + Regression Relevance Propagation for interpretability │
  ├──────────────────────────┼────────────────┼─────────────────────────────────────────────────────────────────────────────────────────┤
  │ Neural Granger Causality │ ICLR 2018      │ Original MLP-based Granger causality discovery                                          │
  └──────────────────────────┴────────────────┴─────────────────────────────────────────────────────────────────────────────────────────┘
  Technical Details:

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                    INGD Architecture (Member B)                         │
  ├─────────────────────────────────────────────────────────────────────────┤
  │                                                                         │
  │  Input: Event embeddings from CMEA (Member A)                          │
  │         h = {h₁, h₂, ..., h_n} for n services                          │
  │                                                                         │
  │  ┌─────────────────────────────────────────────────────────────────┐   │
  │  │  COMPONENT 1: Neural Granger Causal Discovery (from RUN)        │   │
  │  │                                                                 │   │
  │  │  For each pair of services (i, j):                              │   │
  │  │                                                                 │   │
  │  │  1. Restricted model: Predict h_j using only h_j's history     │   │
  │  │     ŷ_j^(R) = MLP(h_j[t-1], h_j[t-2], ..., h_j[t-k])           │   │
  │  │                                                                 │   │
  │  │  2. Full model: Predict h_j using both h_i and h_j history     │   │
  │  │     ŷ_j^(F) = MLP(h_i[t-1], ..., h_j[t-1], ...)                │   │
  │  │                                                                 │   │
  │  │  3. Causal strength: How much does adding h_i improve prediction?│  │
  │  │     Causality(i→j) = ||ŷ_j^(F) - y_j||² / ||ŷ_j^(R) - y_j||²  │   │
  │  │                                                                 │   │
  │  └─────────────────────────────────────────────────────────────────┘   │
  │                              │                                          │
  │                              ▼                                          │
  │  ┌─────────────────────────────────────────────────────────────────┐   │
  │  │  COMPONENT 2: Multi-Kernel Causal Convolution (from CausalFormer)│  │
  │  │                                                                 │   │
  │  │  Capture multi-scale temporal patterns:                         │   │
  │  │  • Kernel size 3: Short-term causality (immediate effects)      │   │
  │  │  • Kernel size 7: Medium-term causality                         │   │
  │  │  • Kernel size 15: Long-term causality (delayed effects)        │   │
  │  │                                                                 │   │
  │  │  Combined: C_ij = Conv1D_k3(h_i, h_j) + Conv1D_k7 + Conv1D_k15  │   │
  │  │                                                                 │   │
  │  └─────────────────────────────────────────────────────────────────┘   │
  │                              │                                          │
  │                              ▼                                          │
  │  ┌─────────────────────────────────────────────────────────────────┐   │
  │  │  COMPONENT 3: Interpretability Layer (from CausalFormer)        │   │
  │  │                                                                 │   │
  │  │  Regression Relevance Propagation (RRP):                        │   │
  │  │  • Backpropagate through the network to find WHICH input       │   │
  │  │    features contributed to each causal edge                     │   │
  │  │                                                                 │   │
  │  │  For edge (Inventory → Order):                                  │   │
  │  │  • RRP shows: "memory_usage" contributed 0.67                  │   │
  │  │               "gc_pause_time" contributed 0.23                  │   │
  │  │               "response_time" contributed 0.10                  │   │
  │  │                                                                 │   │
  │  │  → Explanation: "Memory pressure caused this causal link"       │   │
  │  │                                                                 │   │
  │  └─────────────────────────────────────────────────────────────────┘   │
  │                              │                                          │
  │                              ▼                                          │
  │  Output: Causal Graph G = (V, E, W, Explanations)                      │
  │  • V = services                                                        │
  │  • E = causal edges                                                    │
  │  • W = causal strength weights                                         │
  │  • Explanations = per-edge feature attributions                        │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  What DiagFusion Does (that we improve):
  - Uses GNN with topology-adaptive convolution to learn propagation patterns
  - Learns correlations, not causation
  - No interpretability - can't explain why edges exist

  Our Improvement:
  - Neural Granger discovers true causal relationships (X causes Y, not just X correlates with Y)
  - Multi-kernel convolution captures different time-scale causal effects
  - Relevance propagation explains each edge with feature contributions

  Member C: CCRE (Calibrated Causal Ranking with Explanations)

  What It Does:
  Ranks root cause candidates, provides calibrated confidence scores, and generates human-readable explanations.

  Reference Papers:
  ┌────────────────────────┬──────────────┬───────────────────────────────────────────────────┐
  │         Paper          │    Venue     │               What We Take From It                │
  ├────────────────────────┼──────────────┼───────────────────────────────────────────────────┤
  │ RUN                    │ AAAI 2024    │ Personalized PageRank on causal graph for ranking │
  ├────────────────────────┼──────────────┼───────────────────────────────────────────────────┤
  │ Calibration literature │ Various      │ Temperature scaling for confidence calibration    │
  ├────────────────────────┼──────────────┼───────────────────────────────────────────────────┤
  │ LIME/SHAP              │ ICML/NeurIPS │ Explanation generation concepts                   │
  └────────────────────────┴──────────────┴───────────────────────────────────────────────────┘
  Technical Details:

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                    CCRE Architecture (Member C)                         │
  ├─────────────────────────────────────────────────────────────────────────┤
  │                                                                         │
  │  Input: Causal Graph from INGD (Member B)                              │
  │         G = (V, E, W, Explanations)                                    │
  │         Anomaly signal: which services show symptoms                   │
  │                                                                         │
  │  ┌─────────────────────────────────────────────────────────────────┐   │
  │  │  COMPONENT 1: Personalized PageRank (from RUN)                  │   │
  │  │                                                                 │   │
  │  │  Start from symptom nodes (user-facing failures)                │   │
  │  │  Walk backwards on causal graph to find sources                 │   │
  │  │                                                                 │   │
  │  │  PageRank equation:                                             │   │
  │  │  PR(v) = (1-α) * Σ PR(u) * W(u,v) / out_degree(u)  + α * S(v)  │   │
  │  │                u→v                                              │   │
  │  │                                                                 │   │
  │  │  Where:                                                         │   │
  │  │  • α = restart probability (teleport back to symptoms)          │   │
  │  │  • S(v) = symptom vector (1 for symptom nodes, 0 otherwise)    │   │
  │  │  • W(u,v) = causal edge weight from INGD                        │   │
  │  │                                                                 │   │
  │  │  Output: Ranking scores for each service                        │   │
  │  │  [Inventory: 0.89, Order: 0.12, Cart: 0.03, ...]               │   │
  │  │                                                                 │   │
  │  └─────────────────────────────────────────────────────────────────┘   │
  │                              │                                          │
  │                              ▼                                          │
  │  ┌─────────────────────────────────────────────────────────────────┐   │
  │  │  COMPONENT 2: Confidence Calibration                            │   │
  │  │                                                                 │   │
  │  │  Problem: Neural networks are often OVERCONFIDENT               │   │
  │  │  • Model says 90% confident, but actually correct only 70%     │   │
  │  │                                                                 │   │
  │  │  Solution: Temperature Scaling (Platt Scaling)                  │   │
  │  │                                                                 │   │
  │  │  calibrated_prob = softmax(logits / T)                          │   │
  │  │                                                                 │   │
  │  │  Where T is learned on validation set to minimize:              │   │
  │  │  ECE = Σ |acc(bin) - conf(bin)| * |bin| / N                    │   │
  │  │       bins                                                      │   │
  │  │                                                                 │   │
  │  │  After calibration: "89% confident" means actually ~89% correct │   │
  │  │                                                                 │   │
  │  └─────────────────────────────────────────────────────────────────┘   │
  │                              │                                          │
  │                              ▼                                          │
  │  ┌─────────────────────────────────────────────────────────────────┐   │
  │  │  COMPONENT 3: Explanation Generation                            │   │
  │  │                                                                 │   │
  │  │  Combine:                                                       │   │
  │  │  1. Root cause service + failure type                           │   │
  │  │  2. Causal path from root to symptoms                           │   │
  │  │  3. Edge explanations from INGD                                 │   │
  │  │  4. Evidence from each modality                                 │   │
  │  │                                                                 │   │
  │  │  Template:                                                      │   │
  │  │  "[Root Cause Service] experienced [Failure Type] due to        │   │
  │  │   [Top Contributing Feature]. This caused [Downstream Effect]   │   │
  │  │   in [Affected Services] via [Propagation Path].               │   │
  │  │   Evidence: [Metric Evidence], [Log Evidence], [Trace Evidence]"│   │
  │  │                                                                 │   │
  │  │  Example output:                                                │   │
  │  │  "Inventory Service experienced memory exhaustion due to        │   │
  │  │   memory_usage reaching 95%. This caused timeout errors in     │   │
  │  │   Order Service via the Inventory→Order API dependency.        │   │
  │  │   Evidence: memory_usage: 45%→95%, Log: 'OutOfMemoryError',    │   │
  │  │   Trace: Inventory calls 50ms→3000ms."                         │   │
  │  │                                                                 │   │
  │  └─────────────────────────────────────────────────────────────────┘   │
  │                              │                                          │
  │                              ▼                                          │
  │  Output:                                                               │
  │  {                                                                     │
  │    "ranked_causes": [("Inventory", 0.89), ("Order", 0.12), ...],     │
  │    "calibrated_confidence": 0.89,                                     │
  │    "failure_type": "memory_exhaustion",                               │
  │    "explanation": "Inventory Service experienced...",                 │
  │    "evidence": { "metrics": [...], "logs": [...], "traces": [...] }  │
  │  }                                                                     │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  What DiagFusion Does (that we improve):
  - Uses MaxPooling + FC layer for classification output
  - Ranks instances by event count heuristic (more events = more likely root cause)
  - Raw softmax probabilities (uncalibrated)
  - No explanations

  Our Improvement:
  - PageRank on causal graph for principled ranking
  - Calibrated confidence that operators can trust
  - Natural language explanations with evidence from all modalities

  DiagFusion Implementation Method

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                    DiagFusion Implementation                            │
  ├─────────────────────────────────────────────────────────────────────────┤
  │                                                                         │
  │  STEP 1: Event Extraction                                              │
  │  ─────────────────────────                                             │
  │  • Metrics: 3-sigma anomaly detection → events                         │
  │  • Logs: Drain parsing → template extraction → events                  │
  │  • Traces: Status code counting + 3-sigma on RT → events               │
  │                                                                         │
  │  STEP 2: Event Serialization                                           │
  │  ───────────────────────────                                           │
  │  • Group events by instance-id                                         │
  │  • Sort by timestamp                                                   │
  │  • Event sequence: E_i = [e1, e2, e3, ...]                            │
  │                                                                         │
  │  STEP 3: Event Embedding (fastText)                                    │
  │  ──────────────────────────────────                                    │
  │  • Train fastText on event sequences                                   │
  │  • Supervised mode: predict failure type from sequence                 │
  │  • Output: vector representation for each event                        │
  │                                                                         │
  │  STEP 4: Data Augmentation                                             │
  │  ─────────────────────────                                             │
  │  • Handle imbalanced failure types                                     │
  │  • Replace random event with nearest neighbor in embedding space       │
  │  • Expand each failure type to 1000 samples                           │
  │                                                                         │
  │  STEP 5: Dependency Graph Construction                                 │
  │  ──────────────────────────────────────                                │
  │  • From traces: caller→callee edges (bidirectional)                   │
  │  • From deployment: co-deployed instances share edge                   │
  │                                                                         │
  │  STEP 6: Graph Neural Network                                          │
  │  ────────────────────────────                                          │
  │  • Input: Instance embeddings + dependency graph                       │
  │  • Architecture: Topology-Adaptive Graph Convolution (TAGCN)           │
  │  • K layers with formula: H_K = Σ (D^(-1/2) A D^(-1/2))^k X Θ_k       │
  │                                                                         │
  │  STEP 7: Output Layer                                                  │
  │  ────────────────────────                                              │
  │  • MaxPooling for graph-level representation                           │
  │  • Task #1: FC layer → service group probabilities                    │
  │  • Task #2: FC layer → failure type probabilities                     │
  │  • Joint loss: combines both tasks                                     │
  │                                                                         │
  │  STEP 8: Ranking (Heuristic)                                          │
  │  ──────────────────────────                                            │
  │  • Within predicted service group, rank instances by event count       │
  │  • More anomaly events = higher ranking                                │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  Implementation Details:
  - Framework: Python 3.7.13, PyTorch 1.10.0, DGL 0.9.0
  - Hardware: 12× Intel Xeon E5-2650 v4 @ 2.20GHz, 128G RAM (no GPU)
  - fastText dimension: 100
  - GNN layers: ≤3 (more layers hurt performance)
  - Augmentation size: 1000 samples per class
