  1️⃣ For INGD: Keep Neural Granger BUT Add Hierarchical Scaling

  The Problem:

  Neural Granger alone struggles with 200+ metrics (Train-Ticket has 212).

  The Solution: RCD's Divide-and-Conquer Approach

  From https://proceedings.neurips.cc/paper_files/paper/2022/file/c9fcd02e6445c7dfbad6986abee53d0d-Paper-Conference.pdf:

  Instead of: Full graph causal discovery on 200+ nodes (slow, inaccurate)

  Do this:
  1. Split metrics into small subsets (e.g., 20-30 each)
  2. Run Neural Granger on each subset → find local root cause candidates
  3. Merge candidates recursively
  4. Run final Neural Granger only on merged candidates

  Why this works:
  "RCD detects the root cause by pinpointing without learning the causal structure of the complete graph, which allows the algorithm to run on a much larger set of metrics"

  Implementation:
  def hierarchical_neural_granger(metrics, subset_size=30):
      # Step 1: Cluster metrics by service
      clusters = cluster_by_service(metrics)

      # Step 2: Run Neural Granger on each cluster
      local_candidates = []
      for cluster in clusters:
          candidates = neural_granger(cluster)
          local_candidates.extend(candidates)

      # Step 3: Merge and run final pass
      if len(local_candidates) > subset_size:
          return hierarchical_neural_granger(local_candidates, subset_size)
      else:
          return neural_granger(local_candidates)  # Final precise pass

  2️⃣ For CMEA: Add Cross-Modal Attention (Not Just Contrastive)

  The Problem:

  MULAN already does contrastive learning. You need differentiation.

  The Solution: Multi-dimensional Attention Fusion (MAF)

  From https://arxiv.org/html/2511.17566v1 and TTEDA:

  Instead of just contrastive alignment, add cross-modal attention where each modality attends to others:

  Current (MULAN-like):
  Metrics → Encoder → Embedding
  Logs → Encoder → Embedding
  Traces → Encoder → Embedding
       ↓
  Simple Concatenation or Weighted Sum

  Improved (MAF):
  Metrics → Encoder → M_emb ─────┐
  Logs → Encoder → L_emb ───────┼─→ Cross-Modal Attention → Fused Embedding
  Traces → Encoder → T_emb ─────┘
       ↓
  Each modality queries others: "What in traces explains this metric anomaly?"

  Key innovation from CCLH:
  "Extracts and fuses temporal features of each modality using gated recurrent units (GRUs) and cross-modal attention mechanisms"

  Why this is better:
  - Contrastive learning finds shared representations
  - Cross-modal attention finds explanatory relationships between modalities
  - "What log pattern correlates with this CPU spike?" becomes learnable

  3️⃣ For Causal Graph: Use Hypergraphs Instead of Regular Graphs

  The Problem:

  Regular graphs only capture pairwise (A→B) relationships. Real failures involve multi-way cascades.

  The Solution: CHASE-style Hypergraphs

  From https://arxiv.org/html/2406.19711v1:
  ┌────────────────────────────┬───────────────────────────────────────┐
  │       Regular Graph        │              Hypergraph               │
  ├────────────────────────────┼───────────────────────────────────────┤
  │ Edge connects 2 nodes only │ Hyperedge connects N nodes            │
  ├────────────────────────────┼───────────────────────────────────────┤
  │ A→B, B→C (separate)        │ {A, B, C} (simultaneous cascade)      │
  ├────────────────────────────┼───────────────────────────────────────┤
  │ Misses multi-way causality │ Captures "A affects B, C, D together" │
  └────────────────────────────┴───────────────────────────────────────┘
  CHASE's Results:
  "61.35% accuracy (A@1), representing 36.2% higher performance than the best baseline"

  Implementation concept:
  # Regular graph edge
  edge = (service_A, service_B, weight)

  # Hyperedge captures entire causal path
  hyperedge = {
      "nodes": [service_A, service_B, service_C, service_D],
      "root": service_A,
      "propagation_order": [A→B, A→C, B→D],
      "weight": 0.94
  }

  Why this matters:
  "Each hyperedge represents causality propagation along the invocation path... Traditional graphs model only direct edges between two nodes, while hyperedges can connect multiple nodes simultaneously"

  4️⃣ For Scalability: Add Trace Clustering (Sleuth-style)

  The Problem:

  Processing millions of traces is slow and noisy.

  The Solution: HDBSCAN Trace Clustering

  From https://dl.acm.org/doi/10.1145/3623278.3624758:

  Instead of: Analyze every trace individually

  Do this:
  1. Extract trace features (latency pattern, error codes, call depth)
  2. Cluster similar traces using HDBSCAN
  3. Analyze cluster representatives (not all traces)
  4. Propagate findings to cluster members

  Why HDBSCAN specifically:
  - Handles varying density (some failure patterns are rare)
  - Doesn't require specifying number of clusters
  - Identifies noise/outliers automatically

  Implementation:
  from hdbscan import HDBSCAN

  def cluster_traces(trace_embeddings):
      clusterer = HDBSCAN(min_cluster_size=10, metric='euclidean')
      cluster_labels = clusterer.fit_predict(trace_embeddings)

      # Get representative trace per cluster
      representatives = []
      for cluster_id in set(cluster_labels):
          if cluster_id == -1:  # Skip noise
              continue
          cluster_traces = trace_embeddings[cluster_labels == cluster_id]
          centroid = cluster_traces.mean(axis=0)
          representatives.append(centroid)

      return representatives  # Analyze only these, not millions

  5️⃣ For CCRE: Add Retrieval-Augmented Explanations

  The Problem:

  Generic LLM explanations may not match your specific system.

  The Solution: RAG for Domain-Specific Explanations

  From the survey's mention of Zhang et al. (2023):

  Instead of: LLM generates explanation from scratch

  Do this:
  1. Store past incident explanations in vector DB
  2. When new incident occurs, retrieve similar past incidents
  3. LLM generates explanation using retrieved context
  4. Calibrate confidence based on similarity to past cases

  Benefits:
  - More accurate explanations based on your system's history
  - Confidence calibration improves with more historical data
  - Operators see "Similar to incident X from last month"
