  Comprehensive Project Plan

  Multi-Modal Root Cause Analysis for Microservices: A Systematic Study of Causal Discovery Methods

  Project Duration: 5-6 Months | Team Size: 3

  ---
  Executive Summary

  What This Project IS

  A systematic, transparent study of how different causal discovery algorithms perform for root cause analysis in microservice systems, with:
  - Fair comparison of 4-5 causal methods on the RCAEval benchmark
  - A clean, modular pipeline that shows exactly how multi-modal RCA works
  - Focus on interpretability — not just "what's the root cause" but "how did we get there"
  - A demo dashboard for final presentation

  What This Project is NOT

  - ❌ A claim to beat commercial tools (Dynatrace, incident.io)
  - ❌ A production-ready system
  - ❌ A novel algorithm invention (we're comparing existing approaches)

  Your Unique Angle

  Based on my research, here's what existing work has done and where you differentiate:
  Existing Work: RCAEval benchmark paper (WWW'25)
  What They Did: Compared 15 methods on 735 failure cases
  Your Differentiation: You add multi-modal fusion comparison (they focus on metrics-only)
  ────────────────────────────────────────
  Existing Work: "How Far Are We?" (ASE'24)
  What They Did: Compared 9 causal discovery + 21 RCA methods
  Your Differentiation: You add interpretability analysis (they only measure accuracy)
  ────────────────────────────────────────
  Existing Work: Nezha, Chain-of-Event
  What They Did: Proposed specific multi-modal methods
  Your Differentiation: You do systematic comparison of multiple methods in same framework
  ────────────────────────────────────────
  Existing Work: RUN (AAAI'24)
  What They Did: Neural Granger for RCA
  Your Differentiation: You compare Neural Granger against other methods fairly
  Your contribution: First systematic comparison that evaluates causal methods on accuracy + interpretability + computational cost together, with multi-modal data fusion.

  Algorithm Comparison Framework
  ┌───────────────────┬──────────────────┬─────────────────┬──────────────────┬─────────────────────────────────────┐
  │     Algorithm     │       Type       │ Time Complexity │ Interpretability │              Best For               │
  ├───────────────────┼──────────────────┼─────────────────┼──────────────────┼─────────────────────────────────────┤
  │ PC Algorithm      │ Constraint-based │ O(n^d)          │ ⭐⭐⭐⭐⭐ High  │ Small graphs, when assumptions hold │
  ├───────────────────┼──────────────────┼─────────────────┼──────────────────┼─────────────────────────────────────┤
  │ Granger Causality │ Time-series      │ O(n²p)          │ ⭐⭐⭐⭐ High    │ Temporal data, linear relationships │
  ├───────────────────┼──────────────────┼─────────────────┼──────────────────┼─────────────────────────────────────┤
  │ Neural Granger    │ Deep learning    │ O(n²) per epoch │ ⭐⭐⭐ Medium    │ Non-linear temporal patterns        │
  ├───────────────────┼──────────────────┼─────────────────┼──────────────────┼─────────────────────────────────────┤
  │ DAG-GNN           │ Graph neural net │ O(n² × d)       │ ⭐⭐ Low         │ Complex dependencies                │
  ├───────────────────┼──────────────────┼─────────────────┼──────────────────┼─────────────────────────────────────┤
  │ Attention-based   │ Transformer      │ O(n² × L)       │ ⭐⭐⭐ Medium    │ Multi-modal fusion                  │
  └───────────────────┴──────────────────┴─────────────────┴──────────────────┴─────────────────────────────────────┘

  │ Top-3 Accuracy               │ % of cases where true root cause is in top 3  │ Tolerance for near-misses        │
  ├──────────────────────────────┼───────────────────────────────────────────────┼──────────────────────────────────┤
  │ Top-5 Accuracy               │ % of cases where true root cause is in top 5  │ Broader recall                   │
  ├──────────────────────────────┼───────────────────────────────────────────────┼──────────────────────────────────┤
  │ Mean Average Precision (MAP) │ Mean of AP across all test cases              │ Overall ranking quality          │
  ├──────────────────────────────┼───────────────────────────────────────────────┼──────────────────────────────────┤
  │ Mean Reciprocal Rank (MRR)   │ Mean of 1/rank of true root cause             │ Penalizes lower rankings         │
  ├──────────────────────────────┼───────────────────────────────────────────────┼──────────────────────────────────┤
  │ Inference Time               │ Seconds to produce root cause                 │ Practical usability              │
  ├──────────────────────────────┼───────────────────────────────────────────────┼──────────────────────────────────┤
  │ Memory Usage                 │ Peak RAM during inference                     │ Resource requirements            │
  └──────────────────────────────┴───────────────────────────────────────────────┴──────────────────────────────────┘
  Interpretability Evaluation (Human Study)

  Protocol:
  1. Select 20 failure cases from RCAEval
  2. For each case, show explanations from all 5 algorithms
  3. Ask 10-15 participants (classmates, TAs) to rate:
    - Clarity (1-5): "How easy is it to understand?"
    - Completeness (1-5): "Does it explain the full causal chain?"
    - Actionability (1-5): "Would this help me fix the problem?"
    - Trust (1-5): "Do I believe this explanation?"

  Output: Interpretability score per algorithm

  Final Presentation Structure (15-20 min)

  1. INTRODUCTION (2 min)
     - Problem: Why RCA in microservices is hard
     - Motivation: Many algorithms exist, which to use when?

  2. BACKGROUND (3 min)
     - Brief explanation of causal discovery
     - Overview of 5 algorithms you compared

  3. SYSTEM ARCHITECTURE (3 min)
     - Show architecture diagram
     - Explain data flow: raw data → events → causal graph → root cause

  4. METHODOLOGY (3 min)
     - RCAEval benchmark overview
     - Evaluation metrics (accuracy + interpretability)

  5. RESULTS (4 min)
     - Comparison table
     - Key findings: "Algorithm X best for Y, Algorithm Z best for W"
     - Trade-off analysis: accuracy vs speed vs interpretability

  6. DEMO (3-4 min)
     - Show dashboard
     - Walk through a failure case
     - Show algorithm switching
     - (If live demo) Inject fault and watch diagnosis

  7. CONCLUSION (1-2 min)
     - Summary of findings
     - Recommendations for practitioners
     - Future work
